## Support flow must change before attachments go live (live flow, I did not touch it)
1. `AvenueSupportMessages.Category` is a **Choice** with the 5 fixed values. A category added in AvenueSupportCategories will be **refused by SharePoint on write**. Change the column to Text (or allow fill-in) before staff add categories.
2. The flow's `Valid` check hard-codes `createArray('Booking','Billing','Documents','Equipment','Other')`; it must read AvenueSupportCategories (Active titles) instead, or new categories get "Not accepted".
3. **Trigger**: today "item created", condition `not(empty(MessageId))`. With files the portal creates the item with `Outcome = "Uploading"`, attaches, then MERGEs `Outcome = null`. On the current trigger the flow runs on create **before the files are on it**, writes "Received…", and the portal's MERGE then wipes that Outcome. Change to **"created or modified"** with condition `@and(not(empty(triggerOutputs()?['body/MessageId'])), empty(triggerOutputs()?['body/Outcome']))` (same as the document flow). The flow's own Outcome write then does not re-trigger it. A message without files is still one plain create (no Outcome), so text-only messages work on both the old and new trigger.
4. The flow should re-check attachments (≤ 5 files, ≤ 10 MB, jpg/jpeg/png/heic/heif/webp/pdf) and copy them to a private library linked to the case (§4.8). Not specified in `flows/expressions.md` yet.
5. If an attach fails mid-way the item stays "Uploading" for ever; the thread shows "Not sent — files did not finish uploading". Question: should a staff clean-up sweep those, or should the portal offer "send without files"?
