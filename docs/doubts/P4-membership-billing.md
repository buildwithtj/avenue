# P4 · My membership + Billing — doubts (23 Nov 2026)

1. **AvenuePortal.tsx wiring (P3 owns it).** `MembershipView` now takes an optional `onNavigate?: (tab: 'support') => void`. Without it, the success note names "Messages with Flavors" but there is no "Open Messages" button. The lead needs to pass `onNavigate={setTab}` at `AvenuePortal.tsx:320`.
2. **Hours reset (Q10).** The sheet says hours reset on the 1st (the client wrote "1st"). The meter says "resets on <1st of next month>" for every member. Q10 is still open: is the reset the same for members who pay on another day, and how does the 2-month rollover for new members work? The rollover is not modelled. Hours come from approved requests (`hoursThisMonth`), not the ledger (A5), so the wording says "estimate".
3. **3% on extra hours for legacy plans.** A legacy plan price already includes the card fee. The estimate still adds 3% to that member's extra hours when they pay by card, which matches the existing `overageCents`. The sheet does not say whether this is right. UNKNOWN; ask Flavors.
4. **Unknown pay method.** When `PayMethod` is empty, the page shows the card price (+3%), as `monthlyCharge` already does. This is the Q-M1 default.
5. **Invoice chips.** Stripe has 5 statuses and the screen shows 4 chips. The mapping is draft → Open, uncollectible → Past due, and open past its due date → Past due. `[PROPOSED]`
6. **Paid date.** `IInvoice` has no paid date, and the `AvenueInvoices` select has no paid-at column. The detail sheet shows the amount paid but no date. A `PaidAt` column would need adding to the mirror flow and to readSource. I did not change readSource.
7. **"Recommended" badge** `[PROPOSED]`. It goes on the smallest open plan in the member's group whose hours cover this month's usage so far. It never appears on the current plan.
8. **Legacy members.** A legacy member is offered the current plans of the same kind: Mobile Kitchen if the plan id or name contains "mobile kitchen", otherwise Emerging. Legacy plans are never offered. Whether Flavors wants legacy members to see upgrade cards at all is not confirmed.
9. **Plan change request.** This is one `Billing` support message: subject `Plan change request: <old> → <new>`, and a body with both plans and the member's note. No Stripe object, host request, proration or start date is created. Timing is Q-R2.
10. **Charges this month** lists open invoices next to the estimate lines. If an open invoice is itself this month's plan invoice, the plan amount shows twice: once as an estimate line and once as the invoice. This needs a rule from the client before the lines are de-duplicated.
11. **Typings.** The SCSS class typings come from the build (`temp/sass-ts/.../Site.module.scss.d.ts`). I added the new `mb*`/`bi*` names to that temp file by hand so `tsc --noEmit` passes. The build regenerates the file.
