Avenue · demo

What this is

  • A clickable design prototype in HTML. It is not the built application and is connected to nothing.
  • Members, bookings, readings and invoices are sample entries so the screens are not empty.
  • Every feature shown comes from the client’s scope documents and emails. No prices, allowances or rates are shown, because none have been supplied. “Plan A–C”, “Station 1–3”, “Equipment 1–2” and “Sample Member A–D” are placeholder labels.
  • The green theme and “A” mark are proposals. Brand files have not been supplied.

Member portal: buildable as shown

  • One custom web part (SPFx, React, Fluent UI) on a SharePoint page. SharePoint’s own top bar and site header stay visible, as drawn.
  • Tabs, side panel, timeline, cards and the phone layout are ordinary React and CSS, which a web part allows.
  • Icons shown are stand-ins for Fluent UI icons.
  • Members sign in on Microsoft’s own page as guest accounts. The demo shows a stand-in with no password field.

Staff app: buildable, with limits

  • A Power Apps canvas app using lists, forms, toggles, dialogs and simple charts.
  • On desktop it is shown at 1366×768 scaled to the window. The phone layout shown needs a separate responsive layout in Power Apps, which is extra build effort.
  • Dashboard totals need a summary list refreshed on a schedule, so they are minutes old, not live.

Not ours to design

  • Stripe’s payment and onboarding pages. The demo simulates those steps so the flow can be followed; the real pages are Stripe’s design, not this one.
  • Payments, refunds, retries and emails here are simulated. No money moves and nothing is sent.
  • Emails are simple messages from Microsoft 365 Outlook.
  • B Street’s Power BI reports. The Analytics screen is a stand-in; the real report uses Power BI’s own design.
  • Only the 15-day and 7-day event cancellation rules come from the client. Nothing is shown for other notice periods.

Still to decide
